# Multi-Size Selection and Buy Now / Add to Cart Implementation Plan

## Overview
This plan outlines the architecture and implementation steps to support multiple sizes with per-size stock tracking (stored in Firebase as a Map, e.g., `{"S": 3, "M": 2, "XL": 5}`), interactive size selection on the product details screen, and robust "Add to Cart" and "Buy Now" workflows.

## Firebase Data Structure (`products` collection)
- `sizes`: `Map<String, int>` (e.g., `{"S": 3, "M": 2, "XL": 5}`)
- Total stock can be derived as the sum of all values in `sizes`, or managed alongside.
- Other existing fields remain (`productName`, `price`, `description`, `imageUrl`, `category`).

---

## Proposed Changes by Component

### 1. Product Model (`lib/models/product.dart`)
- Replace or supplement `int stock` with `Map<String, int> sizes`.
- Update `Product.fromMap` / `Product.fromFirestore` to parse `sizes` safely (handling `Map<String, dynamic>`, fallback to empty map or legacy `stock` if needed).
- Compute total stock getter: `int get totalStock => sizes.values.fold(0, (a, b) => a + b);`

### 2. Product Service & Admin Panel (`lib/services/product_service.dart` & `lib/admin/product_management.dart`)
- Update `addProduct` and `updateProduct` to accept `Map<String, int> sizes`.
- Update the admin product form (`ProductManagement`) to provide an interface for managing sizes and their respective stock quantities (e.g., dynamic size-stock inputs or structured key-value manager).

### 3. Cart State (`lib/providers/cart_provider.dart`)
- Update `CartItem` to include `final String selectedSize;`.
- Update `CartProvider.addToCart(Product product, String selectedSize)`:
  - Check stock availability for the specific `selectedSize` from `product.sizes[selectedSize]`.
  - Group cart items by both `product.id` and `selectedSize`.

### 4. Product Details Screen (`lib/user/product_details_screen.dart`)
- Add local state: `String? selectedSize;`.
- Add a visual size selector UI (e.g., `Wrap` with `ChoiceChip` widgets displaying each size and its remaining stock, disabling out-of-stock sizes).
- Validate that `selectedSize != null` before executing "Add to Cart" or "Buy Now". If not selected, show a SnackBar prompt: "Please select a size".
- Pass the chosen `selectedSize` into `CartItem` for both cart addition and direct checkout.

### 5. Checkout & Order Processing (`lib/user/checkout_screen.dart`)
- Update `_validateCart` to check stock of the specific `selectedSize` against `fresh.sizes[item.selectedSize]`.
- Update order item saving to store `selectedSize` in Firestore orders (`items` array).
- Update stock deduction logic on order submission to decrement the specific size key in the product's `sizes` map in Firestore, and trigger an out-of-stock notification if that size stock reaches 0.

---

## User Flow
1. User opens `ProductDetailsScreen`.
2. User views available sizes and stock counts (e.g., S (3), M (2), XL (5)).
3. User selects a size (e.g., "M").
4. User clicks either **Add to Cart** or **Buy Now**.
   - If no size is selected, an error prompt appears.
5. **Add to Cart**: Item with selected size is added to cart; user receives confirmation.
6. **Buy Now**: User is navigated directly to `CheckoutScreen` with the item and selected size; persistent cart remains untouched.
7. User completes checkout; order is placed, stock for the specific size is deducted in Firestore, and orders screen is shown.

## Validation & Testing
1. Verify admin product creation/editing with size maps.
2. Verify size selection UI renders correctly with stock badges.
3. Test "Add to Cart" with specific size and quantity constraints.
4. Test "Buy Now" direct checkout flow with size tracking.
5. Verify Firestore stock updates correctly per size variant.
